# Serenity 傻瓜式部署手册

目标：把本地 `D:\apps\serenity` 上传到 GitHub，再在腾讯云服务器通过 Git 拉取并接入 `serenity.zenithy.art`。

本手册按公开仓库写。公开仓库不需要 Deploy Key；如果以后改成私有仓库，见第 9 节。

## 0. 你需要准备什么

- GitHub 账号：默认按 `YiyuZh` 写。
- GitHub 仓库：默认 `serenity`。
- 腾讯云 Linux CVM：已安装 Docker 和 Docker Compose。
- 域名：`serenity.zenithy.art` 已解析到服务器公网 IP。
- 服务器已有 Caddy 网关，参考项目路径类似 `/opt/apps/hiremate`。
- 外部服务密钥：X API、DeepSeek、飞书机器人、腾讯云 COS。

不要把 `.env`、API key、webhook、COS secret 上传到 GitHub。

## 1. 本地上传前检查

在 Windows PowerShell 执行：

```powershell
cd D:\apps\serenity
git status
```

如果提示 `fatal: not a git repository`，说明还没初始化 Git，继续第 2 节。

检查不能上传的目录是否还存在：

```powershell
Get-ChildItem -Force
Get-ChildItem -Recurse -Force -Directory |
  Where-Object { $_.Name -in @('node_modules','dist','__pycache__','.pytest_cache') } |
  Select-Object FullName
```

如果看到 `frontend\node_modules`、`frontend\dist`、`__pycache__`、`.pytest_cache`，删除它们：

```powershell
Remove-Item -Recurse -Force D:\apps\serenity\frontend\node_modules -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force D:\apps\serenity\frontend\dist -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force D:\apps\serenity\backend\.pytest_cache -ErrorAction SilentlyContinue
Get-ChildItem D:\apps\serenity\backend -Recurse -Force -Directory -Filter __pycache__ |
  Remove-Item -Recurse -Force
```

## 2. 本地功能检查

推荐直接运行一键预检：

```powershell
cd D:\apps\serenity
powershell -ExecutionPolicy Bypass -File .\scripts\verify-local.ps1
```

它会执行后端测试、Python 编译、前端依赖安装、前端类型检查、前端构建、Compose 配置校验、基础敏感信息扫描，并在结束后清理 `node_modules`、`dist`、`__pycache__`、`.pytest_cache`。

如果本机 Docker Desktop 已启动，而且 Docker Hub 或国内镜像源可访问，再执行镜像构建预检：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify-local.ps1 -DockerBuild
```

如果要连容器运行也一起测，执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\smoke-compose.ps1
```

这个脚本会用临时项目名、临时端口 `18000/15173` 和临时 Docker 卷启动整套 Compose，检查 `http://127.0.0.1:18000/api/health` 和 `http://127.0.0.1:15173`，结束后清理临时容器和临时卷。若本机已经有 `serenity-backend` 或 `serenity-frontend` 容器，它会拒绝运行，避免误碰正在跑的实例。

下面是分步命令，排查问题时使用。

后端测试：

```powershell
cd D:\apps\serenity\backend
python -m pytest -q
```

前端构建：

```powershell
cd D:\apps\serenity\frontend
npm install --legacy-peer-deps
npm run typecheck
npm run build
```

Compose 配置检查：

```powershell
cd D:\apps\serenity
$env:POSTGRES_PASSWORD='local-config-check-only'
docker compose config
```

注意：

- `docker compose config` 只检查配置语法，不代表服务器上 `shared_gateway` 网络已经存在。
- `ADMIN_PASSWORD`、`JWT_SECRET`、`POSTGRES_PASSWORD` 是必填项，正式部署必须写在服务器 `.env` 里；上面的 `local-config-check-only` 只用于本地配置检查，不用于启动服务。

如果本机 Docker Desktop 已启动，可以再做镜像构建检查：

```powershell
cd D:\apps\serenity
docker compose build backend frontend
```

如果提示无法连接 `dockerDesktopLinuxEngine`，说明本机 Docker Desktop 没启动，先打开 Docker Desktop 再重跑。

如果能连接 Docker，但卡在 `auth.docker.io` 或 Docker Hub 拉取超时，在当前 PowerShell 先设置国内镜像变量再构建：

```powershell
$env:PYTHON_IMAGE='docker.m.daocloud.io/library/python:3.11-slim'
$env:NODE_IMAGE='docker.m.daocloud.io/library/node:22-alpine'
$env:NGINX_IMAGE='docker.m.daocloud.io/library/nginx:1.27-alpine'
$env:APT_MIRROR_HOST='mirrors.tuna.tsinghua.edu.cn'
$env:PIP_INDEX_URL='https://pypi.tuna.tsinghua.edu.cn/simple'
$env:PIP_TRUSTED_HOST='pypi.tuna.tsinghua.edu.cn'
$env:NPM_REGISTRY='https://registry.npmmirror.com'
docker compose build backend frontend
```

本项目已经验证过：使用上面这组国内镜像变量可以完成 backend 和 frontend 镜像构建。

构建后如果重新出现 `frontend\dist`，上传前可以保留不提交，因为 `.gitignore` 已忽略；更稳妥的做法是按第 1 节清理。

### 7.1 申请 X API 并确认能获取帖子

本项目只读公开 X 帖子，用的是 X API v2 的 App-only Bearer Token。官方入口是 X Developer Console，官方文档说明 Developer Console 用来创建 app、生成凭据、查看用量和购买 credits；Bearer Token 用于 app-only 读取公开数据。

官方参考：`https://docs.x.com/x-api/getting-started/getting-access`、`https://docs.x.com/x-api/users/get-user-by-username`、`https://docs.x.com/x-api/users/get-posts`、`https://docs.x.com/x-api/getting-started/pricing`、`https://docs.x.com/x-api/fundamentals/rate-limits`。

操作步骤：

1. 打开 `https://console.x.com/`，用你的 X 账号登录。
2. 按页面提示创建 developer account。如果页面要求填写 use case，写清楚用途：读取指定公开账号 `@aleabitoreddit` 的公开 Posts，用于内部运营同步、翻译和飞书群通知，不做登录、不发帖、不点赞、不评论、不私信。
3. 在 Developer Console 里创建 Project 和 App。
4. 进入这个 App 的 `Keys and tokens` 页面，找到或生成 `Bearer Token`。
5. 立刻把 Bearer Token 保存到密码管理器或服务器 `.env`，不要发到聊天、截图、GitHub、README、日志里。
6. 如果控制台提示需要购买 credits 或启用 billing，先按 X 控制台要求完成，否则接口可能返回 `403` 或额度不足。

在本地 PowerShell 先测 X API：

```powershell
$env:X_BEARER_TOKEN='粘贴你的 X Bearer Token'
$handle='aleabitoreddit'

$user = Invoke-RestMethod `
  -Headers @{ Authorization = "Bearer $env:X_BEARER_TOKEN" } `
  -Uri "https://api.x.com/2/users/by/username/$handle"

$user.data.id

$tweets = Invoke-RestMethod `
  -Headers @{ Authorization = "Bearer $env:X_BEARER_TOKEN" } `
  -Uri "https://api.x.com/2/users/$($user.data.id)/tweets?max_results=5&tweet.fields=id,text,created_at,lang,conversation_id,referenced_tweets,attachments,author_id,entities,public_metrics&expansions=attachments.media_keys,referenced_tweets.id&media.fields=media_key,type,url,preview_image_url,width,height,alt_text"

$tweets.data | Select-Object id,text,created_at
```

通过标准：

- `$user.data.id` 能打印出一串数字 user id。
- `$tweets.data` 能看到至少 0 到 5 条公开帖子。账号没有公开新帖时可能为空，但请求不能报 `401/403/429`。
- `401` 通常是 Bearer Token 错误或复制多了空格。
- `403` 通常是 app 权限、access tier、billing 或 credits 没开通。
- `429` 是触发 X API 限流，等 reset 时间后再试，或降低 `X_MAX_RESULTS`、`X_MAX_PAGES`。

把通过测试的值写入服务器 `.env`：

```bash
X_ACCOUNT_HANDLE=aleabitoreddit
X_BEARER_TOKEN=<刚刚测试通过的 Bearer Token>
X_MAX_RESULTS=10
X_MAX_PAGES=3
POLL_INTERVAL_SECONDS=180
```

### 7.2 配置 DeepSeek 翻译

1. 打开 DeepSeek 控制台，创建或复制 API Key。
2. 写入服务器 `.env`：

```bash
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_API_KEY=<DeepSeek API Key>
DEEPSEEK_MODEL=deepseek-v4-pro
```

本项目调用 OpenAI-compatible `POST /chat/completions`，并显式使用 `thinking={"type":"disabled"}`，避免翻译任务返回推理过程；翻译 prompt 要求保留数字、时间、链接、代码、专有名词和事实含义。

官方参考：`https://api-docs.deepseek.com/`。

### 7.3 配置飞书群机器人

1. 打开目标飞书群。
2. 进入群设置，找到机器人或 Bots。
3. 添加 `自定义机器人 / Custom Bot`。
4. 复制 webhook URL，写入 `.env` 的 `FEISHU_WEBHOOK_URL`。
5. 如果你在飞书里开启了签名校验，把飞书显示的 secret 写入 `FEISHU_WEBHOOK_SECRET`；如果没有开启签名，这一项留空。

```bash
FEISHU_WEBHOOK_URL=<飞书群自定义机器人 webhook>
FEISHU_WEBHOOK_SECRET=<开启签名才填写>
```

飞书自定义机器人只在当前群聊内生效，通过 webhook 单向推送消息。当前代码会发送富文本 post 消息：原文、中文翻译、原帖链接、发布时间、图片链接。图片优先使用 COS 链接；如果 COS 归档失败，会附上 X 原始图片链接并标记未归档，避免正文和译文被卡住。

官方参考：`https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot`。

### 7.4 外部服务闭环验收

启动容器后，先跑一次外部服务检查：

```bash
cd /opt/apps/serenity
docker compose exec backend python -m app.cli check-integrations --send-feishu-test
```

通过标准：

- 终端输出 `X API ok`，并显示 `user_id` 和 `fetched=<数量>`。
- 终端输出 `DeepSeek ok`，并显示一小段译文。
- 终端输出 `Feishu ok: test message sent`。
- 飞书群里能收到 `Serenity integration check ok...` 测试消息。

再跑一次真实同步：

```bash
docker compose exec backend python -m app.cli sync-once
docker compose logs --tail=120 worker
```

通过标准：

- `sync-once` 输出 `fetched=<数量> new=<数量> processed=<数量>`。
- 如果有新帖，后台会写入 `posts`，执行翻译和推送。
- 飞书群消息包含原文、中文翻译、原帖链接和图片链接。
- 前端看板能看到新帖子状态；失败时可以在详情页查看生命周期并执行 Retry 或 Skip。

如果服务器拉 Docker Hub 慢或超时，也把下面这组构建变量写进 `.env`：

```bash
PYTHON_IMAGE=docker.m.daocloud.io/library/python:3.11-slim
NODE_IMAGE=docker.m.daocloud.io/library/node:22-alpine
NGINX_IMAGE=docker.m.daocloud.io/library/nginx:1.27-alpine
APT_MIRROR_HOST=mirrors.tuna.tsinghua.edu.cn
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
PIP_TRUSTED_HOST=pypi.tuna.tsinghua.edu.cn
NPM_REGISTRY=https://registry.npmmirror.com
```

保存后检查不要把 `.env` 提交：

```bash
git status --short
```

正常情况下 `.env` 不会出现在输出里。

如果你没有替换占位密码，后端会故意启动失败，并提示：

```text
Unsafe production configuration
```

这是安全保护，不是 Docker 故障。回到 `.env` 修改 `ADMIN_PASSWORD`、`JWT_SECRET`、`POSTGRES_PASSWORD`、`DATABASE_URL` 后再启动。

如果 `ADMIN_PASSWORD`、`JWT_SECRET` 或 `POSTGRES_PASSWORD` 为空，`docker compose config` 或 `docker compose up` 会直接失败并提示必须设置对应变量。这是为了避免服务用弱默认密钥启动，或 PostgreSQL 用弱默认密码创建数据卷。

RELEASE_ID=$(date +%Y%m%d-%H%M%S)

serenity.zenithy.art {

    @serenity_api path /api/*
    handle @serenity_api {

    handle {

```bash
cd /opt/apps/hiremate

docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile
```

正式访问：

```bash

```

```text

```

- 用户名：`.env` 的 `ADMIN_USERNAME`
- 密码：`.env` 的 `ADMIN_PASSWORD`

## 10. 如果以后改成私有仓库：Deploy Key 流程

公开仓库不需要这一节。

在服务器生成项目专用 key：

```bash
ssh-keygen -t ed25519 -C "serenity-deploy-key" -f ~/.ssh/serenity_deploy_key
cat ~/.ssh/serenity_deploy_key.pub
```

把输出的公钥复制到 GitHub：

```text
GitHub 仓库 -> Settings -> Deploy keys -> Add deploy key
```

只拉代码不推送时，不要勾选 write access。

配置服务器 SSH alias：

```bash
nano ~/.ssh/config
```

加入：

```sshconfig
Host github.com-serenity
    HostName github.com
    User git
    IdentityFile ~/.ssh/serenity_deploy_key
    IdentitiesOnly yes
```

测试：

```bash
ssh -T git@github.com-serenity
```

成功输出类似：

```text
Hi YiyuZh/serenity! You've successfully authenticated, but GitHub does not provide shell access.
```

这表示成功，不是错误。

私有仓库 clone 地址要写成：

```bash
git clone git@github.com-serenity:YiyuZh/serenity.git serenity
```

不要把 deploy key 公钥当成仓库地址。

## 13. 常见错误

### 13.1 `502 Bad Gateway`

检查 Caddy 能不能解析容器名：

```bash
docker network inspect shared_gateway | grep serenity
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
```

检查 Serenity 是否启动：

```bash
cd /opt/apps/serenity
docker compose ps
docker compose logs --tail=100 backend
docker compose logs --tail=100 frontend
```

### 13.2 `shared_gateway declared as external, but could not be found`

创建网络：

```bash
docker network create shared_gateway
```

然后重启：

```bash
cd /opt/apps/serenity
docker compose up -d
```

### 13.3 登录失败

检查 `.env`：

```bash
grep -E 'ADMIN_USERNAME|JWT_SECRET|CORS_ORIGINS' .env
```

不要把密码贴到聊天或 GitHub issue。

### 13.4 DeepSeek 不工作

检查 `.env`：

```bash
grep -E 'DEEPSEEK_BASE_URL|DEEPSEEK_MODEL' .env
```

确认：

- `DEEPSEEK_BASE_URL=https://api.deepseek.com`
- `DEEPSEEK_MODEL=deepseek-v4-pro`
- `DEEPSEEK_API_KEY` 已填写，但不要打印完整 key。

### 13.5 前端页面刷新 404

确认前端镜像使用的是本项目的 `frontend/nginx.conf`，里面必须有：

```nginx
try_files $uri $uri/ /index.html;
```

### 13.6 GitHub push 失败

检查 remote：

```powershell
cd D:\apps\serenity
git remote -v
```

公开仓库 HTTPS 地址：

```text
https://github.com/YiyuZh/serenity.git
```

SSH 地址：

```text
git@github.com:YiyuZh/serenity.git
```

这两个都是仓库地址。Deploy Key 是另一段 `ssh-ed25519 ...` 开头的公钥，不要混用。
